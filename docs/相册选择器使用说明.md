# 相册选择器使用说明

项目提供五个可复用模块：

- `:album-api`：只包含媒体模型、MediaStore/Photo Picker 数据访问、权限辅助、会话持久化、文件复制和压缩，不依赖 Compose 或其他 UI。
- `:album-ui-view`：基于 Android View 和 RecyclerView 的全屏相册选择页。
- `:album-ui-compose`：提供可嵌入内容区 `AlbumPickerContent` 和完整页面 `AlbumPicker`。
- `:album-video-api`：仅包含视频播放工厂、播放器与状态协议，无 Media3 / Compose / Coil 依赖。
- `:album-video-media3`：可选 Media3 实现，宿主按需依赖并注册，不是 UI 模块的传递依赖。

## 环境要求

- Android 最低版本：API 24。
- 发布仓库：JitPack。
- Compose UI 只适用于已经启用 Jetpack Compose 的宿主模块。
- View UI 不要求宿主使用 Compose。

## 宿主依赖

在宿主项目的 `settings.gradle.kts` 添加 JitPack：

```kotlin
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven("https://jitpack.io")
    }
}
```

宿主应用按需依赖 UI 模块；两个 UI 模块都会传递 `album-api`。把 `Tag` 替换为已经发布的 Git 标签：

```kotlin
val albumVersion = "Tag"

implementation("com.github.sceneren.Album:album-ui-view:$albumVersion")
implementation("com.github.sceneren.Album:album-ui-compose:$albumVersion")
```

只使用媒体数据、系统 Photo Picker、相机和文件处理能力时，可单独依赖：

```kotlin
implementation("com.github.sceneren.Album:album-api:$albumVersion")
```

在本仓库内调试源码时，也可以继续使用 `implementation(project(":album-ui-view"))` 等项目依赖。

为避免资源合并冲突，`:album-ui-view` 的资源统一使用 `auv_` 前缀，
`:album-ui-compose` 的资源统一使用 `auc_` 前缀。

宿主仍需要在 `AndroidManifest.xml` 声明媒体读取权限：

```xml
<uses-permission
    android:name="android.permission.READ_EXTERNAL_STORAGE"
    android:maxSdkVersion="32" />
<uses-permission android:name="android.permission.READ_MEDIA_IMAGES" />
<uses-permission android:name="android.permission.READ_MEDIA_VIDEO" />
<uses-permission android:name="android.permission.READ_MEDIA_VISUAL_USER_SELECTED" />
```

UI 模块会在内部发起权限请求。只使用 `album-api` 或由宿主自行控制权限时，使用
`AlbumMediaPermissionRequestFactory.create(filter)`，这样“只选图片”“只选视频”和“图片和视频”会分别请求对应权限。
相机入口调用系统拍照或录像 Activity，不需要宿主声明 `CAMERA` 权限。`album-api` 的 FileProvider 和 Photo Picker
回移服务、`album-ui-view` 的选择页 Activity 都会通过 Manifest 合并自动注册。

## 配置宿主图片加载器

两个 UI Library 不依赖 Coil、Glide 等第三方图片加载库。宿主必须在
`Application.onCreate` 中分别配置 View 和 Compose 图片加载器。配置会同时用于网格缩略图、
图片预览和视频封面；`target` 可用于区分加载尺寸或解码质量。网格缩略图应从实际 UI
约束解析尺寸，不要由宿主硬编码或向 UI 传递像素宽高。

以下是宿主演示模块使用 Coil 的示例，宿主也可以替换为其他实现：

```kotlin
val imageLoader = ImageLoader.Builder(this)
    .components { add(VideoFrameDecoder.Factory()) }
    .build()

com.github.sceneren.album.ui.view.AlbumUi.setImageLoader(
    object : com.github.sceneren.album.ui.view.AlbumImageLoader {
        override fun load(
            imageView: ImageView,
            media: AlbumMedia,
            target: com.github.sceneren.album.ui.view.AlbumImageTarget,
        ) {
            imageView.load(media.uri, imageLoader)
        }

        override fun clear(imageView: ImageView) {
            imageView.load(null, imageLoader)
        }
    },
)

com.github.sceneren.album.ui.compose.AlbumUi.setImageLoader(
    com.github.sceneren.album.ui.compose.AlbumImageLoader { media, target ->
        val isGridThumbnail =
            target == com.github.sceneren.album.ui.compose.AlbumImageTarget.GRID_THUMBNAIL
        val model = if (isGridThumbnail) {
            val sizeResolver = rememberDrawScopeSizeResolver()
            remember(media.uri, media.dateModifiedEpochSeconds, sizeResolver) {
                ImageRequest.Builder(this)
                    .data(media.uri)
                    .size(sizeResolver)
                    .build()
            }
        } else {
            media.uri
        }
        rememberAsyncImagePainter(
            model = model,
            imageLoader = imageLoader,
            contentScale = if (isGridThumbnail) ContentScale.Crop else ContentScale.Fit,
        )
    },
)
```

Compose 的 `DrawScopeSizeResolver` 从网格 `Image` 的实际绘制范围取尺寸；View 的
`imageView.load(...)` 会通过 `ImageView` target 自动使用单元格的布局尺寸。两种实现都无需传入固定宽高。
使用 Coil 的 `rememberDrawScopeSizeResolver()` 时，需要在包含配置代码的函数上添加
`@OptIn(ExperimentalCoilApi::class)`。

必须把该 `Application` 配置到宿主 Manifest，确保选择页在进程恢复后仍能取得加载器。

```xml
<application
    android:name=".App"
    ... />
```

### 大图加载与小图占位

图片预览通过 View 的 `AlbumImageLoader.loadPreview(imageView, media)` 和 Compose 的
`AlbumImageLoader.previewPainter(media)` 请求大图。这两个方法默认转发到原有的
`PREVIEW_IMAGE` 分支，已有宿主实现和 lambda 可以继续使用。

Coil 使用官方的 `placeholderMemoryCacheKey` 关联小图与大图请求：

```kotlin
// 网格请求：缓存小图，Key 应同时包含 URI 和媒体修改信息。
val thumbnailKey = "thumbnail:${media.uri}:${media.dateModifiedEpochSeconds}:${media.sizeBytes}"
val thumbnail = ImageRequest.Builder(context)
    .data(media.uri)
    .memoryCacheKey(thumbnailKey)
    .size(thumbnailEdge, thumbnailEdge)
    .scale(Scale.FIT)
    .precision(Precision.INEXACT)
    .build()

// 预览请求：小图只作占位；完整图片独立缓存并按显示尺寸采样。
val preview = ImageRequest.Builder(context)
    .data(media.uri)
    .memoryCacheKey("preview-original:${media.uri}:${media.dateModifiedEpochSeconds}:${media.sizeBytes}")
    .placeholderMemoryCacheKey(thumbnailKey)
    .size(previewEdge, previewEdge)
    .scale(Scale.FIT)
    .precision(Precision.INEXACT)
    .build()
```

这里的尺寸是 Coil 的解码上限，预览组件仍使用 `FIT_CENTER` / `ContentScale.Fit` 完整显示画幅。
提供方可能把携带 `ContentResolver.EXTRA_SIZE` 的读取请求转换为裁剪缩略图，因此 Photo Picker
大图应通过原始授权 URI 的 `openAssetFileDescriptor(uri, "r")` 读取，不向提供方传缩略图尺寸。
demo 的 `PhotoPickerImageFetcher.Factory(preferOriginal = true)` 实现了这一路径；它是宿主适配，
不属于 UI Library 的公开 API。完整接线见 `app/.../App.kt`。

缓存中没有小图时，demo 会并发请求有界缩略图和大图；大图成功后始终替换小图，失败时保留小图，
切换媒体、回收或离开页面会取消旧请求。UI Library 继续由宿主决定具体的图片加载实现。
方案参考 [Coil 官方缓存占位示例](https://coil-kt.github.io/coil/recipes/#using-a-memory-cache-key-as-a-placeholder)。

## 自定义 Toast

两个 UI 模块分别提供可选的 `AlbumToastHandler`，在 `Application.onCreate()` 中注册到实际使用的模块。库内的选择数量限制、选择失败、拍摄失败和结果处理失败等 Toast 提示，都会交给宿主显示：

```kotlin
import android.widget.Toast

val appContext = applicationContext
com.github.sceneren.album.ui.view.AlbumUi.setToastHandler { message ->
    // 可以替换为宿主现有的 Toast 工具或自定义布局。
    Toast.makeText(appContext, message, Toast.LENGTH_LONG).show()
}
com.github.sceneren.album.ui.compose.AlbumUi.setToastHandler { message ->
    Toast.makeText(appContext, message, Toast.LENGTH_LONG).show()
}
```

也可以实现对应 UI 模块中的 `AlbumToastHandler.showToast(message: CharSequence)` 接口再注册。

- 回调在主线程执行，仅接收 `message`，保留完整的 `CharSequence` 提示内容。示例中的 `appContext` 为在 Application 初始化时获取的 Application Context。
- 注册后由宿主负责提示的样式、显示时长及自定义提示的清理，库不会额外显示系统 Toast。
- Compose 的 `AlbumPicker` 和 `AlbumPickerContent` 共用此配置，View 选择页及其预览触发的 Toast 提示也使用对应配置。
- 未注册时默认使用系统短 Toast；传入 `null` 可以恢复默认行为。
- 配置为进程级持有，不要在实现中捕获或长期保存 Activity。两个 UI 模块的配置互相独立，仅需配置实际使用的模块。

```kotlin
com.github.sceneren.album.ui.view.AlbumUi.setToastHandler(null)
com.github.sceneren.album.ui.compose.AlbumUi.setToastHandler(null)
```

## 可选视频播放与自定义引擎

视频播放与图片加载一样由宿主配置。两个 UI 模块只传递轻量 `album-video-api`，未提供播放器时继续通过 `AlbumImageLoader` 的 `VIDEO_COVER` 展示静态视频封面和原有预览工具栏，不创建解码器、不显示胶囊操作栏。

### 使用提供的 Media3 实现

按需添加独立依赖（只使用静态封面或其他引擎时无需添加）：

```kotlin
implementation("com.github.sceneren.Album:album-video-media3:$albumVersion")
```

在 `Application.onCreate()` 注册到实际使用的 UI 模块：

```kotlin
import com.github.sceneren.album.video.media3.Media3AlbumVideoPlayerFactory

val videoPlayerFactory = Media3AlbumVideoPlayerFactory()
com.github.sceneren.album.ui.view.AlbumUi.setVideoPlayerFactory(videoPlayerFactory)
com.github.sceneren.album.ui.compose.AlbumUi.setVideoPlayerFactory(videoPlayerFactory)
```

- 视频页仅显示悬浮返回（沿用 `backIconRes` 或当前默认返回图标）和底部半透明胶囊操作栏：播放/暂停、拖动进度、静音/取消静音。图片页缩放、选择和确认保持不变，视频选择仍可在网格完成。
- 默认自动播放、静音；静音偏好在本次预览中共享。静音预览不申请音频焦点，避免打断其他音频。播放完成停在末帧，点击播放重播；错误时提示并可点击重试。
- 只有当前已停稳且宿主处于 `RESUMED` 的视频拥有播放器，翻页拖动、后台和退出都会释放，返回时恢复本次预览内的位置与暂停意图。预加载相邻页仅展示封面，不启动解码器。
- 使用 `content://` URI 直接播放，不为预览复制文件，不新增权限；宿主仍负责相应 URI 的读取授权。封面仍通过图片加载器加载。
- 注册配置供后续打开的预览使用；传 `null` 清除配置并恢复静态封面。初始化应在 Application 中完成，以覆盖进程恢复。

```kotlin
com.github.sceneren.album.ui.view.AlbumUi.setVideoPlayerFactory(null)
com.github.sceneren.album.ui.compose.AlbumUi.setVideoPlayerFactory(null)
```

Compose 的完整页面和嵌入内容均支持按次覆盖。省略参数时使用 `AlbumUi` 配置；显式传 `null` 时即使全局注册过也只展示静态封面：

```kotlin
AlbumPicker(
    config = pickerConfig,
    onResult = onResult,
    onCancel = onCancel,
    videoPlayerFactory = null,
)
// AlbumPickerContent 同样支持 videoPlayerFactory 参数。
```

### 使用其他播放方式

不需要依赖 `album-video-media3`。实现 `com.github.sceneren.album.video.AlbumVideoPlayerFactory`，每次 `create(context)` 返回独立 `AlbumVideoPlayer` 即可；两个 UI 使用同一个协议，不需要分别实现 Compose 播放器。

协议要点：

- `view`：无父容器、按比例完整显示视频的 Android View，UI 会负责挂载；不要叠加默认传输控件。
- `load(uri, positionMs, playWhenReady, muted)`：异步加载并应用起始位置、播放和静音意图；provider/文件读取和解码不能阻塞主线程。
- `snapshot()` 返回 `AlbumVideoPlaybackState`，包括进度、时长、播放意图、实际播放、结束/错误、可 seek 和首帧状态；读取必须轻量。未知时长为 0。
- `onChanged`：在主线程通知状态、错误和首帧变化；首帧后 UI 才隐藏封面。实际播放中 UI 每 250ms 更新进度，暂停和后台不轮询。
- `setPlaying` / `setMuted` / `seekTo` / `retry`：由选择器的统一操作栏调用；静音仅影响该播放器，不改系统音量。
- `release()`：幂等释放 surface、监听器和解码器，停止之后的回调；不要移除由 UI 管理的父容器。调用方不应再复用已释放实例。
- 所有接口由主线程调用。引擎应处理音频焦点、耳机拔出等音频中断，不持有已销毁的 Activity。

```kotlin
val customFactory = AlbumVideoPlayerFactory { context ->
    MyVideoPlayer(context) // 宿主实现 AlbumVideoPlayer
}
com.github.sceneren.album.ui.view.AlbumUi.setVideoPlayerFactory(customFactory)
com.github.sceneren.album.ui.compose.AlbumUi.setVideoPlayerFactory(customFactory)
```

完整协议及每个方法的约定见 `album-video-api` 中的 `AlbumVideoPlayer` KDoc。仅依赖 UI 或自定义实现时，依赖树不应出现 `androidx.media3`。

## 使用选择页

先创建两种 UI 共用的选择配置：

```kotlin
val pickerConfig = AlbumPickerConfig(
    mediaFilter = AlbumMediaFilter.IMAGES_AND_VIDEOS,
    maxSelectionCount = 20,
    camera = AlbumCameraConfig(enabled = true),
    compression = AlbumCompressionConfig(
        enabled = true,
        skipAtOrBelowKb = 100,
    ),
)
```

### View

View 模块通过 `ActivityResultContract` 打开独立选择页，输出 `AlbumPickerResult?`：

```kotlin
private val picker = registerForActivityResult(
    com.github.sceneren.album.ui.view.AlbumPickerContract(),
) { result ->
    result?.items.orEmpty().forEach { item ->
        // item.filePath 是最终文件的真实绝对路径
        // item.originalFilePath 是复制到 photo_picker 目录的原始文件路径
    }
}

picker.launch(
    com.github.sceneren.album.ui.view.AlbumPickerRequest(
        config = pickerConfig,
    ),
)
```

未配置 `animation` 时，View 实现会使用组件自带的默认动画：选择页从屏幕底部弹出，关闭时向底部退出。
宿主可在每次启动请求中传入自己的四个动画资源：

```kotlin
picker.launch(
    com.github.sceneren.album.ui.view.AlbumPickerRequest(
        config = pickerConfig,
        animation = com.github.sceneren.album.ui.view.AlbumPickerAnimation(
            openEnterResId = R.anim.host_album_picker_open_enter,
            openExitResId = R.anim.host_album_picker_open_exit,
            closeEnterResId = R.anim.host_album_picker_close_enter,
            closeExitResId = R.anim.host_album_picker_close_exit,
        ),
    ),
)
```

四个字段依次控制选择页打开进入、宿主打开退出、宿主关闭进入和选择页关闭退出。
传 `animation = null` 会显式关闭本次打开和关闭的全部 Activity 动画；单个字段传 `0` 可只关闭对应阶段。

### Compose

Compose 模块不声明 Activity，也不提供 Activity Result Contract。宿主把 `AlbumPicker` 作为普通
Composable 放入自己的导航或条件布局，并在完成或取消回调后退出该组件：

```kotlin
var showPicker by rememberSaveable { mutableStateOf(false) }
var lastResult by remember { mutableStateOf<AlbumPickerResult?>(null) }

if (showPicker) {
    com.github.sceneren.album.ui.compose.AlbumPicker(
        config = pickerConfig,
        appearance = com.github.sceneren.album.ui.compose.AlbumPickerAppearance(),
        onResult = { result ->
            lastResult = result
            showPicker = false
        },
        onCancel = { showPicker = false },
    )
} else {
    Button(onClick = { showPicker = true }) {
        Text("打开 Compose 相册")
    }
}
```

组件内部仍负责权限请求、系统 Photo Picker、相机、分页、目录、预览、选择会话和最终文件处理；
宿主负责组件显示和结果处理。完整页面使用 `animation` 配置进出转场，传 `null` 或
`AlbumPickerAnimation.None` 可关闭动画。宿主应在完成/取消回调后移除页面。

#### 完整页面系统栏

`AlbumPicker` 包含标题、返回/取消、目录选择、内容、预览及底部确认栏。通过参数控制两栏颜色与图标：

```kotlin
AlbumPicker(
    config = pickerConfig,
    onResult = onResult,
    onCancel = onCancel,
    systemBarStyle = AlbumPickerSystemBarStyle(
        statusBarColor = android.graphics.Color.WHITE,
        navigationBarColor = android.graphics.Color.BLACK,
        darkStatusBarIcons = true,
        darkNavigationBarIcons = false,
        navigationBarContrastEnforced = false,
    ),
)
```

颜色为 `null` 时跟随选择器工具栏/底栏，图标明暗为 `null` 时自动根据背景亮度决定。
默认在退出组合时恢复宿主 Window 原样式；有统一系统栏管理器时传 `systemBarStyle = null`。
页面同时绘制系统栏边距的背景，以适配强制 edge-to-edge；深色导航栏图标从 API 26 起有效。

#### 嵌入已有页面

`AlbumPickerContent` 仅提供目录切换、网格、拍摄/添加入口、可选权限入口和区域内预览。
它不修改系统栏、不增加系统栏边距、不提供页面标题或底部确认栏，也不播放全屏转场。
宿主使用同一个 `AlbumPickerState` 读取选择状态并触发操作：

```kotlin
val pickerState = rememberAlbumPickerState()
Column(Modifier.fillMaxSize()) {
    Text("选择照片") // 宿主标题栏
    AlbumPickerContent(
        config = pickerConfig.copy(
            singleSelectionFinishMode = SingleSelectionFinishMode.EXPLICIT_CONFIRM,
        ),
        state = pickerState,
        onResult = onResult,
        onCancel = onCancel,
        modifier = Modifier.fillMaxWidth().weight(1f),
    )
    Row { // 宿主底部栏
        Button(onClick = pickerState::preview, enabled = pickerState.canConfirm) {
            Text("预览")
        }
        Button(onClick = pickerState::confirm, enabled = pickerState.canConfirm) {
            Text("确认(${pickerState.selectedItems.size})")
        }
        Button(onClick = pickerState::cancel, enabled = !pickerState.isProcessing) {
            Text("取消")
        }
    }
}
```

给内容区明确高度或使用 `weight`，不要放进纵向无限约束的滚动容器。
`confirm()` 执行同一套文件复制/压缩流程；`preview()` 打开已选预览；`refresh()` 检查并更新变化的内容。

View、Compose 完整页面和嵌入内容都会在回到前台时重新校验媒体，并在前台监听提供方的增删变化。
没有变化时不刷新 Pager，也不清空元数据缓存；检测到变化后复用当前列表，以 URI 差异更新增删改条目，保留可见文件与滚动偏移。
分页加载前后检查数据一致性；增删导致偏移变化时丢弃旧代分页结果，按幸存文件 URI 恢复已加载窗口，再继续分页，避免重复或漏图。
部分授权合并列表按去重后的顺序计算分页偏移，避免同一文件同时存在于持久授权和 MediaStore 时重复或遗漏。
`cancel()` 优先关闭预览，再次调用才取消会话。普通返回键交给宿主；目录/预览展开时组件处理返回。
一个 state 只能绑定一个活动内容组件；退出组合后操作失效，重建时选择会话仍由组件保存恢复。
`IMMEDIATE` 单选策略在嵌入模式下仍有效，需要宿主确认按钮时应设置 `EXPLICIT_CONFIRM`。
仓库 demo 同时演示完整页面与嵌入模式。

两套实现都通过各自包内的 `AlbumPickerAppearance` 配置。工具栏、底栏、预览背景、文字颜色以及返回、相机、
相册标题下拉箭头、选择状态、视频播放等图标都可以由宿主覆盖。标题下拉箭头使用独立的图片资源，不与标题文字拼接。View 网格还可通过
`gridItemSpacingDp` 和 `gridSpanCount` 配置 item 间距与单行数量。

`maxSelectionCount` 必须在 1 到 100 之间。设置为 1 时，可将
`singleSelectionFinishMode` 配置为 `IMMEDIATE`，选中后立即完成；默认值
`EXPLICIT_CONFIRM` 需要用户点击“完成”。

## 仅使用 album-api

不需要内置 UI 时，宿主可以直接创建 `AlbumApi`。建议按应用级实例复用：

```kotlin
val albumApi = AlbumApi.create(applicationContext)
val accessStatus = albumApi.getMediaAccessStatus(AlbumMediaFilter.IMAGES)
val mediaFeed = albumApi.getMediaFeed(
    mediaFilter = AlbumMediaFilter.IMAGES,
    pageSize = 50,
)
```

`mediaFeed.pagingData` 是 `Flow<PagingData<AlbumMedia>>`。完整授权时数据来自 MediaStore；部分授权或未授权时，
数据来自已经持久化的 Photo Picker 选择列表。宿主自行使用 Photo Picker 时，可调用：

```kotlin
val launcher = albumApi.registerPhotoPicker(
    activity = this,
    mediaFilter = AlbumMediaFilter.IMAGES_AND_VIDEOS,
    maxSelectionCount = 9,
) { result ->
    // 处理 PhotoPickResult.Selected、Cancelled 或 Failed
}

launcher.launch()
```

持久分页按页读取元数据，不逐张打开历史媒体；同一轮分页复用系统授权清单与相机快照，并在加载前后检查其是否变化。
仅使用数据 API 的宿主为列表保留一个 `albumApi.createMediaChangeTracker(filter)`，在首次加载前调用 `hasChanges()` 建立基线。
回到前台、或收到 `observeMediaChanges()` 通知时，再调用挂起方法 `hasChanges()`；结果为 `true` 才刷新当前 Paging 列表和目录，失败时保留原列表。
监听应绑定界面可见生命周期；同一过滤条件、目录和访问状态下复用当前 Pager 与滚动状态。
Android 11+ 完整授权时优先通过卷版本/世代复用元数据签名；旧系统及部分授权使用流式元数据比较，均不解码整库图片或视频。
授权文件检查只使实际变化 URI 的缓存失效；图片和预览缓存包含提供方支持的修改世代，能识别同秒同大小的文件修改。
在系统相册删除文件后，即使系统仍保留该 URI 的授权，也会通过 MIME/元数据查询识别失效文件并移出列表。
提供方无法返回元数据时，仅对该 URI 探测文件描述符的可读性，不读取或解码媒体内容；临时提供方故障会保留旧缓存，避免误删仍可读取的文件。
`invalidateMediaCache()` 仍可用于宿主显式维护，但不应在每次回到前台时无条件调用。
需要完整可读性清理时显式调用 `reconcilePersistedSelections()`。分页加载失败时，View/Compose 选择器均提供重试入口。

注册必须在 Activity 进入 `STARTED` 前完成。若宿主自行注册 Activity Result，可把返回 URI 交给
`albumApi.processPhotoPickerResult(...)`，复用授权校验、元数据解析和持久化逻辑。

## 结果文件路径和压缩

列表分页、目录读取和部分授权同步只读取 URI 与元数据，不批量复制原始媒体。勾选、取消勾选和取消会话也不会生成媒体副本；只有用户点击确认（或配置为单选即完成时明确选中一项）才调用 `confirm()`，复制最终选中项。缩略图和预览由宿主图片加载器直接读取原始 URI，不应先复制整个列表。

用户在 UI 中确认的每一个媒体都会先流式复制到：

```
<getExternalFilesDir(null)>/photo_picker/
```

在真实设备上通常对应：

```
/sdcard/Android/data/<应用包名>/files/photo_picker/
```

单张图片复制上限为 256 MiB，复制前及流式写入时均检查；视频不使用此图片上限。超限或取消会清理未完成临时文件，已完成的共享缓存继续保留。

复制过程使用有限大小缓冲区、临时文件和原子改名。缓存键由 URI、API 30+ 的 `GENERATION_MODIFIED`（低版本回退 `DATE_MODIFIED`）和文件大小组成；命中且大小有效时直接复用。批量处理任意一项失败时只清理未完成的临时文件，已提交缓存继续保留，选择页保持打开。

结果项字段含义如下：

- `originalUri`：用户选择的原始 `content://` 或相机 URI。
- `originalFilePath`：`photo_picker` 目录中的原始复制文件绝对路径。
- `filePath`：宿主实际应处理的最终文件绝对路径。未启用压缩或跳过压缩时与 `originalFilePath` 相同；图片压缩成功时为 Luban 输出文件路径；视频始终不压缩。
- `resultUri`：最终文件对应的 URI，适合需要 URI 授权的下游组件使用。
- `compressionStatus`：记录未启用、按大小跳过、已压缩或视频不适用。

压缩默认关闭。开启后，大小小于等于 `skipAtOrBelowKb` 的图片不会压缩；压缩使用
[Luban](https://github.com/Curzibn/Luban)。

这些目录属于应用专属外部存储，卸载应用时会被系统清理。相同媒体的多个选择结果可能复用同一路径，因此删除单个文件属于缓存驱逐，调用前应确保其他结果不再使用该路径。宿主可以调用：

```kotlin
AlbumApi.create(context).clearGeneratedMedia(context)
AlbumApi.create(context).deleteGeneratedMedia(context, item.filePath)
```

不要把 `filePath` 当作可跨应用共享的 URI；跨应用传递时应使用 `resultUri`，并按需授予临时 URI 权限。

## 权限、分页和相机恢复

- `FULL` 权限使用 MediaStore 分页和文件夹列表。
- `PARTIAL` 权限直接使用系统 MediaStore 查询已授权媒体，并结合系统 `ContentResolver.persistedUriPermissions` 与相机拍摄记录合并分页。
- `DENIED` 权限通过系统 `ContentResolver.persistedUriPermissions` 与应用相机目录读取已授权媒体，无需本地 Room 数据库。
- Photo Picker 选择会通过系统保留可用的持久读取授权。
- 相机拍摄前会把待写入 URI、文件路径和会话配置写入应用会话存储。宿主重建并恢复选择组件显示后，会继续恢复相机会话并接收拍摄结果。
- 相机默认入口开启；混合媒体模式可通过 `AlbumCameraConfig.mixedMediaCaptureType` 指定拍照或录像。

## 预览行为

- 点击底部“预览”只浏览当前已选媒体。
- 点击网格媒体会从当前项开始浏览当前相册数据；滑动到已加载列表末端前会自动继续分页，
  不会在打开预览时一次性读取整个相册。
- View 使用 `ViewPager2 + ZoomImageView`，Compose 使用
  `HorizontalPager + ZoomImage` 基础组件。Compose UI Library 不使用
  `CoilZoomAsyncImage`，本地媒体的 Painter 完全由宿主加载器提供。
- 图片完整显示并支持缩放；视频不创建缩放组件。未提供视频引擎时只显示宿主封面和静态播放图标，
  配置可选引擎后由当前前台视频页负责播放，详见“可选视频播放与自定义引擎”。
- 从可见网格图片进入预览时，图片会从单元格的裁剪区域展开到完整图片的等比显示区域。
  Compose 使用共享元素过渡并支持返回动画；View 使用 Dialog 内的缩略图 Drawable 过渡，
  不复制原始位图。没有可见来源图片时使用普通预览入口，视频播放仍由可选引擎负责。

### Photo Picker 图片兼容性

实况标签优先采用提供方的格式代码或 JPEG/HEIC/HEIF XMP 标识，不再仅凭 `MVIMG_` 文件名前缀判断。
新选择的图片缺少格式元数据时最多读取 1 MiB 头部进行探测，读取失败不阻止普通图片入库。
宿主 demo 对 Photo Picker 图片使用 `PhotoPickerImageFetcher` 从原始授权 URI 读取流，
避免部分提供方的文件描述符不兼容；视频仍使用视频解码器。该 Coil 适配位于 `app`，UI Library 保持加载器无关。
