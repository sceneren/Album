# Module: app

`:app` is the demonstration host for five reusable Album libraries. Its package/namespace is `com.github.sceneren.photopicker` (see `gradle.properties`), with min SDK 24 and compile/target SDK 37.

- `MainActivity` demonstrates View full-page selection, Compose full-page selection, and `AlbumPickerContent` embedded between host title/actions. It consumes results without duplicating media data handling.
- `App` configures Coil-backed loaders for both UI modules and video decoding. Grid requests use `SystemThumbnailFetcher` (`ContentResolver.loadThumbnail`, API 29+) first, with size-bounded original fallback; Compose uses bounded device-derived request sizes so painter restarts do not wait for a draw-size resolver. Preview requests use a versioned original-only cache namespace separate from grid thumbnails, explicit FIT/inexact bounded decoding, and no provider EXTRA_SIZE hints for image originals.
- `PhotoPickerImageFetcher` handles authorized Photo Picker image content streams. Size-hinted reads are optional: a missing/unsupported sized asset falls back once to the same URI via `openAssetFileDescriptor(uri, "r")` with no size hint, preserving asset offsets/length and Coil's decode size. Preview requests (preferOriginal) and requests without pixel dimensions go directly to the original; cancellation and permission errors are not retried. Coil remains in the host, outside both UI libraries and `album-api`.
- Thumbnail requests have a versioned URI/modification-generation/metadata cache key separate from previews and use FIT/inexact validation for aspect-preserving system thumbnails. Both host loaders synchronously seed cached grid thumbnails for cells, image previews and video covers; preview originals retain independent cache validation and replace placeholders on success. Uncached previews load bounded thumbnails concurrently with originals; View auxiliary requests are cancelled on rebind, clear, detach and lifecycle stop, and cannot overwrite a completed original. Provider/cache misses still require asynchronous loading.
- `App` registers optional `Media3AlbumVideoPlayerFactory` for both UI modules. Removing that dependency/registration leaves static video covers; custom playback engines can implement `album-video-api` without Media3.
- `ui/theme` owns host Material3 styling.

Project dependencies: `:album-api`, `:album-ui-view`, `:album-ui-compose`, `:album-video-media3`. Verify with `:app:testDebugUnitTest`, `:app:assembleDebug`, and `:app:lintDebug`. Real provider compatibility, system bars and media/permission flows still require device validation.
